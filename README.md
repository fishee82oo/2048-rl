# Deep Reinforcement Learning for 2048

A minimal, readable PyTorch project that trains a standard Deep Q-Network to play
2048 and compares it with random and immediate-reward greedy baselines. The game
and learning algorithm are implemented directly, without external RL libraries.

## RL formulation

- **State:** the 4×4 board transformed with `log2(tile)`, empty cells set to zero,
  and flattened to 16 float32 values. The raw board remains a NumPy integer array.
- **Actions:** `0 = up`, `1 = down`, `2 = left`, `3 = right`.
- **Game reward:** the score gained by merging tiles on that move.
- **Training reward:** game reward plus optional strategy shaping (enabled by default).
- **Goal:** maximize long-term discounted cumulative reward.

Each tile merges at most once per move. A changed board receives exactly one new
tile (90% 2, 10% 4); unchanged moves receive no new tile. Games end when no valid
move exists, and continue after reaching 2048. `reset()` returns the observation;
`step(action)` returns `(next_state, reward, done, info)` with score and maximum tile.

## Model and learning

```text
16 → Linear(16,128) → ReLU → Linear(128,128) → ReLU → Linear(128,4)
```

The outputs are Q-values with no softmax. Epsilon-greedy behavior samples only
valid moves during exploration and masks invalid Q-values during exploitation.
Evaluation and playback call `training=False`, giving effective epsilon zero.
Strategy checkpoints also apply the corner-preserving filter before action selection.

The replay buffer stores `(state, action, reward, next_state, done)`, where reward
is the shaped training reward when strategy is enabled. Each update
samples a minibatch and minimizes Huber loss against the standard DQN target:

```text
terminal:      target = reward
non-terminal:  target = reward + gamma * max_a Q_target(next_state, a)
```

The maximum in the learning target uses all four target-network outputs, as in
the requested formula; only behavior action selection is masked. This keeps the
five-field replay format simple, but untrained invalid-action values may affect
bootstrapping. This is ordinary DQN, not Double DQN.

| Setting | Default |
| --- | --- |
| Discount gamma | 0.99 |
| Adam learning rate | 0.001 |
| Batch size | 128 |
| Replay capacity | 100,000 |
| Epsilon | Linear decay from 1.0 to 0.05 over 100,000 training actions |
| Target synchronization | Every 1,000 optimizer updates |
| Gradient norm clipping | 10 |
| Training episodes | 5,000 |
| Evaluation games per agent | 100 |
| Seed | 42 |

Training performs one optimizer update per move once 128 transitions are
available. Huber loss and gradient clipping help control large raw merge rewards.
The greedy baseline simulates each valid slide without spawning tiles or changing
the environment, chooses the highest immediate merge reward, and breaks ties randomly.

## Installation

Use Python 3.9 or newer (including the macOS Python 3.9.6 environment).
Pip selects dependency releases compatible with your Python version. From this directory:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

On Windows, activate with `.venv\Scripts\activate` instead.

## Training

```bash
python train.py --episodes 5000 --seed 42 --strategy
```

Progress prints every 100 episodes and at completion. The best checkpoint is
selected by single-episode training game score; the final checkpoint saves the
last policy. This selection is noisy and does not imply the best average policy.
Each run starts fresh and overwrites the standard result and checkpoint paths.
Default outputs are resolved relative to the scripts. Use `--output-dir` for
separate runs; relative custom paths are resolved from the working directory.

## Evaluation

```bash
python evaluate.py --games 100 --seed 42
```

This loads `checkpoints/best_model.pt`, runs 100 complete games per agent, and
reports average and median score, average maximum tile, best score/tile, average
moves, and the percentage reaching at least 128, 256, 512, 1024, and 2048.
All agents use the same per-game environment seed sequence; different moves
still lead to different boards. Use a separate seed (e.g. `--seed 10000`) for
held-out evaluation. To evaluate the final policy instead:

```bash
python evaluate.py --checkpoint checkpoints/final_model.pt
```

## Watch the agent play

```bash
python play.py
python play.py --delay 0.05 --seed 10000
```

The board and score print after every move. Use `--delay 0` for immediate playback.
There is no GUI and no artificial move limit.

## Results and verification

Plots and per-episode metrics are in `results/`. Game score includes merges only.
`total_reward` is a compatibility alias for `training_reward`; it can differ from
score when strategy shaping is on. The CSV separately records summed `game_reward`,
`strategy_reward`, and `training_reward`, plus the strategy flag. `corner_occupancy`
is the percentage of post-move boards anchored in the corner; `snake_score` and
`empty_cells` are averages over post-move boards, including the final board.
Evaluation averages per-game occupancy and snake quality equally across games. `evaluation.csv` contains the
aggregate comparison, and `evaluation_games.csv` records every game. Policy
weights are in `checkpoints/`; binary checkpoints are ignored by Git by default.

The original `results/run_notes.md` describes the initial **10-episode smoke test**.
Existing root results and checkpoints are preserved by this modification and may
have been updated by later user runs. New strategy verification artifacts live
in `runs/strategy_smoke`, `runs/vanilla_smoke`, and `runs/comparison_smoke`; see
`runs/strategy_verification.md` for measured results. They verify the pipeline and do not demonstrate convergence or strong
play. No claim is made that this small DQN outperforms greedy play or reaches 2048.

Run the tests:

```bash
python -m unittest discover -s tests -v
```

Tests cover merge examples, all four directions, spawning, invalid actions,
terminal detection, simulation side effects, network shape, replay copying,
action masking, Bellman targets, target synchronization, and checkpoint round trips.

The project uses CPU execution with one PyTorch thread and seeds Python, NumPy,
PyTorch, and the environment's local generator. Identical software/hardware and
seeds should reproduce runs; different versions or platforms can differ.
New checkpoints contain policy weights and a `strategy` boolean, not replay, optimizer, or RNG state,
so they support evaluation and playback rather than exact training resumption.
Original weight-only checkpoints still load and default to vanilla behavior.
Evaluation/playback use the saved strategy setting unless `--strategy` or
`--no-strategy` explicitly overrides filtering. Strategy constants remain in
source code; archive that source alongside experiments for reproducibility.


## Strategy-Aware Reward Shaping

The optional heuristic encourages keeping the maximum tile in the **top-right**,
organizing tiles along a descending snake, preserving empty spaces, and avoiding
destruction of an organized board for a small merge. This is a heuristic strategy,
not an original 2048 rule or a guarantee of stronger play.

```text
128   256   512   1024
 64    32    16      8
  .     .     2      4
  .     .     .      .
```

`utils/strategy.py` defines every strategy constant:

| Constant | Value |
| --- | --- |
| `CORNER_WEIGHT` | 4.0 |
| `SNAKE_WEIGHT` | 2.0 |
| `EMPTY_WEIGHT` | 0.5 |
| `STRATEGY_SCALE` | 8.0 |
| `CORNER_BREAK_PENALTY` | -16.0 |
| `CORNER_CAPTURE_BONUS` | 8.0 |
| `SNAKE_WEIGHTS` | 16, 15, …, 1 |

The path starts at `(0,3)`, moves left across row 0, right across row 1,
left across row 2, then right across row 3. Let `v` be log2 tiles in that order,
with zeros for empty cells, and `w = [16, 15, …, 1]`:

```text
positional = dot(w, v) / dot(w, sort_descending(v))
monotonicity = 1 - sum(max(v[i+1] - v[i], 0)) / sum(max(v[i], v[i+1]))
snake_quality = (positional + monotonicity) / 2
```

Both components are normalized to [0,1]. Descending arrangements get 1; upward
jumps are penalized according to their log magnitude. Trailing zeros introduce
no violation. An empty board has snake quality 0; a zero pair denominator uses
monotonicity 1. Positional normalization compares the same tile multiset in its
ideal order, avoiding large raw tile magnitudes.

The exact shaping formula is:

```text
anchored(B) = max(B) > 0 and B[0,3] == max(B)
corner(B) = log2(max(B)) if anchored(B), otherwise 0
Phi(B) = 4 * corner(B) + 2 * snake_quality(B) + 0.5 * empty_cells(B)/16

transition_bonus = -16 if anchored before and not after
                    +8 if not anchored before and anchored after
                     0 otherwise
strategy_reward = 8 * (Phi(new_board) - Phi(old_board)) + transition_bonus
training_reward = game_reward + strategy_reward
```

The new board includes the normal random tile spawn. Thus spawn randomness can
influence shaping; simulations used for filtering deliberately do not spawn.
Unchanged boards earn zero shaping. No terminal potential reset is applied.
Losing an anchored 1024 costs roughly 336 reward before snake/empty changes,
whereas large merges still earn their full game reward. One extra empty cell
alone contributes 0.25 to the training reward. These are initial, untuned weights.

For action selection, simulate each legal move using `simulate_action()`. If the
maximum is anchored, retain only moves with a maximum still in the top-right
and a corner value at least as large as the old maximum. A merge at the corner
is allowed. Tied maxima count as anchored; the board stores values, not tile
identities. If no preserving move exists, retain all legal moves. Apply this
before both random exploration and greedy Q selection. Baselines remain unfiltered.
No direction is hard-coded, and simulation changes neither board, score, nor RNG.

The DQN architecture, replay, and Bellman update remain unchanged. The target
maximum still ranges over all four target-network outputs, including actions
excluded by behavior filtering. The system combines reward shaping and a policy
constraint, so occupancy improvements alone do not prove the network learned
corner preservation. The filter can exclude a beneficial temporary corner break.
The requested plain potential difference (rather than `gamma*Phi(next)-Phi(now)`)
and asymmetric transition bonuses do not guarantee preservation of the original
optimal policy. No improvement in game score is assumed.

Train both variants with separate outputs:

```bash
python train.py --episodes 5000 --seed 42 --no-strategy --output-dir runs/vanilla
python train.py --episodes 5000 --seed 42 --strategy --output-dir runs/strategy
```

Compare both checkpoints with identical held-out game seeds (DQN is vanilla,
DQN_compare is strategy; the CSV also records checkpoint paths and filter flags):

```bash
python evaluate.py --games 100 --seed 10000 \
  --checkpoint runs/vanilla/checkpoints/best_model.pt \
  --compare-checkpoint runs/strategy/checkpoints/best_model.pt \
  --output-dir runs/comparison
```

To inspect learned behavior without enforcing the filter, repeat with
`--no-strategy --output-dir runs/comparison_unfiltered`. This overrides action
filtering only; it does not change how saved weights were trained.

```bash
python play.py --checkpoint runs/strategy/checkpoints/best_model.pt
python -m unittest discover -s tests -v
```

Each new training run adds `corner_occupancy_curve.png` and `snake_score_curve.png`
to its results folder alongside score, maximum tile, and training reward plots.
